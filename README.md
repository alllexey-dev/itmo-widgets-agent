# itmo-widgets-agent

Свой клиент ITMO.Widgets (бета). Маленькая фоновая программа, которую вы запускаете на своём
ноутбуке, NAS или сервере. Она получает события от сервера ITMO.Widgets и действует от вашего
имени в вашей сессии My ITMO: главное - записывает на физкультуру из очереди, когда телефон
этого сделать не может (например, на iPhone без пушей).

Один статический бинарник без зависимостей, в простое занимает несколько мегабайт памяти.

Неофициальный проект, не связан с Университетом ИТМО.

## Установка

Нужен телефон с ITMO.Widgets, где вы уже вошли, и доступ к бете (его включает администратор).

Linux и macOS, в терминале:

```sh
curl -fsSL https://raw.githubusercontent.com/alllexey-dev/itmo-widgets-agent/main/install.sh | sh
```

FreeBSD (`fetch` есть в базовой системе, `curl` не нужен):

```sh
fetch -qo - https://raw.githubusercontent.com/alllexey-dev/itmo-widgets-agent/main/install.sh | sh
```

Windows, в PowerShell:

```powershell
irm https://raw.githubusercontent.com/alllexey-dev/itmo-widgets-agent/main/install.ps1 | iex
```

Скрипт показывает, что уже есть (версия агента и последняя на GitHub, подключён ли телефон, работает ли
служба), и меню: установить или обновить, подключить к телефону, включить, выключить или перезапустить
службу, статус и логи, отключить агента (`unpair`), удалить полностью. Пункты, которые сейчас не имеют
смысла, не показываются; отключение и удаление спрашивают подтверждение.

Установка берёт последний релиз (включая предварительные), сверяет SHA-256 с `SHA256SUMS` и спрашивает,
запускать ли агента в фоне как службу (автозапуск). Если служба уже есть, обновление её просто перезапускает.
Права администратора нужны только для службы на FreeBSD:

- Linux: `~/.local/bin/itmo-widgets-agent`, служба `systemd --user` и `loginctl enable-linger`, чтобы
  агент работал и после выхода из системы. Логи: `journalctl --user -u itmo-widgets-agent -f`.
- macOS: `~/.local/bin/itmo-widgets-agent`, агент launchd `dev.alllexey.itmo-widgets-agent`. Логи:
  `~/Library/Logs/itmo-widgets-agent.log`.
- Windows: `%LOCALAPPDATA%\itmo-widgets-agent`, задача планировщика «ITMO.Widgets agent» при входе в
  Windows, без окна. Логи: `agent.log` в той же папке.
- FreeBSD: `~/.local/bin/itmo-widgets-agent`, скрипт rc.d `/usr/local/etc/rc.d/itmo_widgets_agent`
  (`daemon(8)`, агент работает от вашего пользователя, включается через `sysrc`). Для этого нужен root:
  скрипт покажет команды и выполнит их через `sudo` или `doas`, только если вы согласитесь, иначе просто
  напечатает их. Логи: `/var/log/itmo_widgets_agent.log`.

Без терминала (Docker, CI, скрипты) меню и вопросов нет: скрипт ставит агент и службу. Действие можно задать
флагом, например `curl -fsSL .../install.sh | sh -s -- --uninstall --yes`. Флаги: `--install`, `--pair`,
`--service on|off|restart`, `--status`, `--unpair`, `--uninstall`, `--no-service`, `--version v0.1.0`
(или `IW_VERSION`), `--yes`. В PowerShell те же параметры с одним дефисом:

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/alllexey-dev/itmo-widgets-agent/main/install.ps1))) -Uninstall -Yes
```

Повторная установка обновляет агент на месте и перезапускает службу. Удаление останавливает службу,
выполняет `unpair` и удаляет программу и файл службы; в папке настроек остаются только `state.json` и
`agent.env`, без токенов.

### Бинарник вручную

Скачайте файл для своей системы со [страницы релизов](https://github.com/alllexey-dev/itmo-widgets-agent/releases):
`itmo-widgets-agent-<os>-<arch>` для `linux-amd64`, `linux-arm64`, `darwin-amd64`, `darwin-arm64`,
`freebsd-amd64`, `freebsd-arm64` или `windows-amd64.exe`, и рядом `SHA256SUMS`. Переименуйте в `itmo-widgets-agent`, положите в `PATH` и
подключите. Например, macOS на Apple Silicon:

```sh
shasum -a 256 --ignore-missing -c SHA256SUMS    # на Linux: sha256sum, на FreeBSD: sha256 -q <файл>
install -m 755 itmo-widgets-agent-darwin-arm64 /usr/local/bin/itmo-widgets-agent
xattr -d com.apple.quarantine /usr/local/bin/itmo-widgets-agent   # если скачали браузером: бинарник не подписан
itmo-widgets-agent pair
itmo-widgets-agent run
```

Файлы хранятся в `/data`, если такая папка есть, иначе в папке настроек пользователя
(`~/.config/itmo-widgets-agent` на Linux и FreeBSD, `~/Library/Application Support/itmo-widgets-agent` на
macOS). Другую папку задаёт `IW_STATE_DIR`. Примеры службы для автозапуска лежат в `deploy/`:
`launchd` для macOS, `systemd --user` для Linux и rc.d для FreeBSD.

### Docker

```sh
curl -O https://raw.githubusercontent.com/alllexey-dev/itmo-widgets-agent/main/compose.yaml
docker compose run --rm agent pair
docker compose up -d
```

Без токена `run` не завершается, а ждёт, пока `pair` его сохранит: так `restart: unless-stopped` не
перезапускает контейнер по кругу. Подключить заново можно при запущенном контейнере той же командой
`docker compose run --rm agent pair`.

## Подключение

`pair` показывает QR-код и ссылку. Ссылка действует 2 минуты, не пересылайте её.

1. На телефоне: ITMO.Widgets -> Профиль -> "Подключить устройство" -> отсканируйте QR. Можно навести
   обычную камеру телефона или вставить ссылку в поле.
2. Сверьте код проверки на телефоне и в терминале, нажмите "Подключить".
3. Агент напишет "Подключено" и сохранит токен и сессию.

Если запустить `itmo-widgets-agent` в терминале без токена, он сам откроет экран подключения.

Если сессия ИТМО закрылась (например, вы вышли из ITMO.ID), агент пришлёт уведомление и перестанет
записывать. Выдайте новую сессию, не перезапуская агент:

```sh
itmo-widgets-agent pair --session
```

Запасной вариант без QR: `itmo-widgets-agent login` читает из stdin refresh-токен ITMO.ID (и токен
агента `iwa_...`, если его ещё нет). Токены никогда не передаются аргументами или переменными
окружения.

## Экран

В терминале `run` и `pair` рисуют экран: подключение с QR, ссылкой и кодом проверки, а потом состояние -
связь с сервером, срок сессии ИТМО, последние события и попытки записи на физкультуру. Клавиши: `s` - новая
сессия ИТМО, `u` - отключить агент (как `unpair`), `q` - выйти. Если агент отключили на сервере, экран
показывает «отключено»: `p` - подключить заново, `q` - выйти с кодом 3.

В Docker, в службе или при выводе в файл экрана нет: агент пишет обычные логи (JSON, по строке на событие), а
`pair` печатает QR и ссылку в лог. Режим можно задать явно: `--ui=tui`, `--ui=plain` или `IW_UI`. `NO_COLOR`
отключает цвета.

## Что делает

- записывает на занятие из вашей очереди на физкультуру, когда сервер сообщает о свободном месте:
  перепроверяет очередь, смотрит, не записаны ли вы уже, и записывается;
- сообщает серверу результат: запись удалась, ИТМО отказал (запись в очереди отменяется) или мест
  нет (запись остаётся в очереди);
- присылает уведомления через [ntfy](https://ntfy.sh), если задан `IW_NOTIFY_NTFY_URL`: запись,
  отказ, заявки в друзья, закрытая сессия.

## Чего не делает

- не опрашивает расписание и свободные места сам: действует только по событиям сервера;
- не делает больше 60 запросов в час к ИТМО;
- не выходит из ITMO.ID и не отзывает токены: сессия общая с телефоном;
- не записывает других людей. Один агент - один аккаунт, только свой.

## Приватность

- Токен ИТМО хранится только на вашей машине (`session.json`, права 0600). Сервер ITMO.Widgets его
  не видит: при подключении телефон передаёт сессию зашифрованной, ключ есть только у агента.
- Агент работает в той же сессии My ITMO, что и телефон. Выход из ITMO.ID или "завершить сеансы"
  там отключит и телефон, и агент.
- Отключение агента в "Подключённых устройствах" сразу закрывает ему доступ к серверу; при
  следующем запросе агент удалит токен и сессию сам и завершится с кодом 3.
- В логах и на экране нет токенов, имён и названий занятий; всё, что похоже на токен, логгер дополнительно
  маскирует.
- Сессия даёт полный доступ к My ITMO. Безопасность машины, где запущен агент, на вас.
- Публичный ntfy.sh видит текст уведомлений. Лучше свой сервер ntfy или топик с длинным случайным
  именем.

## Настройки

| Переменная | По умолчанию | Что это |
|---|---|---|
| `IW_BACKEND_URL` | `https://widgets.alllexey.dev` | сервер ITMO.Widgets |
| `IW_STATE_DIR` | `/data` или папка настроек | где лежат файлы агента |
| `IW_AGENT_TOKEN_FILE` | `$IW_STATE_DIR/agent-token` | токен агента |
| `IW_FEATURES` | `sport,friends` | что включено |
| `IW_NOTIFY_NTFY_URL` | нет | топик ntfy, например `https://ntfy.sh/my-long-random-topic` |
| `IW_AGENT_NAME` | имя машины | как агент называется в "Подключённых устройствах" |
| `IW_UI` | `auto` | `tui` - экран, `plain` - логи, `auto` - экран, только если запущен в терминале |
| `IW_LOG_LEVEL` | `info` | `debug`, `info`, `warn` или `error` |

Те же ключи можно записать в `$IW_STATE_DIR/agent.env` строками `KEY=VALUE`; переменные окружения
важнее файла.

Команды: `run` (по умолчанию), `pair [--session]`, `login`, `status`, `unpair`, `health`, `version`;
`--help` показывает справку. Коды выхода: 0 - успех, 1 - ошибка, 2 - неверные аргументы или настройки,
3 - токен агента отозван, 4 - ИТМО не принял сессию.

`unpair` сначала просит сервер отозвать токен агента (как удаление в "Подключённых устройствах": агент
пропадает из списка в приложении), потом удаляет токен и сессию ИТМО с этой машины. Запущенная служба с
этим токеном на следующем запросе получит отказ и остановится. Если сервер ещё не умеет отзывать токен
по просьбе агента или недоступен, `unpair` всё равно удалит файлы, скажет об этом и попросит удалить
агент в приложении: Профиль -> "Подключённые устройства".

## Ограничения

- Бета: сервер включает агента только пользователям из списка.
- Если ИТМО запретит повторное использование refresh-токенов, подключение перестанет работать:
  `pair` скажет "ИТМО не принял сессию".
- Максимальный срок сессии ITMO.ID общий с телефоном: когда он истечёт, войдите в приложение
  заново и снова выполните `pair --session`.
- Пока агент на связи, записью на физкультуру занимается он, а не телефон. Если агент выключен
  больше трёх минут или без сессии ИТМО, записывает телефон.

## Для разработчиков

Сборка, тесты и устройство проекта: [CONTRIBUTING.md](CONTRIBUTING.md). Лицензия MIT.

К ИТМО агент ходит своим минимальным клиентом: обновление токена ITMO.ID, список записей на
физкультуру и запись на занятие, больше ничего. Это осознанное исключение из правила "только
[MyItmoApi](https://github.com/alllexey123/MyItmoApi)": MyItmoApi остаётся эталонной реализацией,
форматы запросов и ответов сверяются с ним.
